# Personalized profile avatars

Members can create a FamSync character from a selfie in **Account → Profile → Create my avatar**, on web and Android. They take or choose a photo, agree to photo processing, generate a preview, then choose **Use avatar** or **Try again**. Their current avatar changes only when they save. **Reset avatar** restores the app's existing default.

Saved avatars can also become six personalized [chat stickers](avatar-stickers.md), available from the sticker button beside chat's emoji controls.

## Runtime

- The API normalizes a still JPEG, PNG or WebP photo (up to 5 MB and 40 megapixels), corrects orientation, strips metadata and resizes it to at most 1024 pixels. Android also uses its existing photo normalization before upload.
- Gemini receives the photo and the bundled `apps/api/assets/avatars/style.webp` as separate identity and style references. The output is re-encoded as a 512-pixel WebP. No photo or generated bytes are logged or included in the job payload.
- Generation is saved in the outbox as `avatar.generate`. An account can reserve five attempts per UTC day and have one queued/running generation. Reusing the same upload ID with the same normalized photo resumes the request without using another attempt. Temporary failures get up to three processing attempts; permanent failures are shown to the member. A per-generation advisory lock prevents simultaneous workers from generating the same portrait. Saved output is reused after a worker restart. A crash after the provider completes but before the output is stored can still repeat a paid provider request.
- Original photos and previews use the existing private attachment bucket. Selfies are removed after terminal processing; a scheduled cleanup at 24 hours also removes interrupted uploads and unused previews. The running scheduler and storage availability determine when cleanup can complete. Saved portraits remain until replacement, reset or account deletion; those actions queue cleanup as well.
- The Gemini Interactions request sets `store: false`. This disables interaction-history storage; it is not a promise about every aspect of the provider's data handling. See [Google's data-retention documentation](https://aistudio.google.com/docs/interactions-overview#data-storage-retention).

## Access and display

Generation status and preview URLs are owner-only under row-level security. Saving a portrait changes the account profile, independently of name/bio edits. Batch resolution shares only the accepted portrait with the owner, current family members, and current participants of a shared conversation (including valid guests). Removing family membership or revoking guest access ends new lookups. Existing signed image URLs expire within 60 seconds.

Both apps' shared Avatar components resolve user IDs through `/api/v1/avatars/resolve`, so existing avatar placements display the saved portrait. Lookup requests are batched and deduplicated. Signed URLs live only in memory, in a cache scoped to the viewing account, and refresh periodically. Saving/resetting invalidates the local portrait cache immediately; other sessions see changes on their next lookup. The app's existing defaults handle missing or unavailable portraits. Demo identities do not make API requests.

The saved-avatar resolver replaces the originally proposed expansion of every person response; this keeps profile image access and expiry checks in one place.

## Enable and release

Apply all earlier project migrations, then these migrations in order:

1. `20261212000000_add_personal_avatars.sql`
2. `20261213000000_queue_avatar_account_cleanup.sql`

Deploy the API and web app and produce a new Android build. The API needs its existing private-storage and jobs settings, a running outbox scheduler, and a Gemini API key with access to the image model. The API asset `assets/avatars/style.webp` must be included with the deployment.

Server-only settings:

- `GEMINI_API_KEY`: existing provider key, from a billed project suitable for the intended users and photo processing. The existing Family Base AI provider/age considerations still require a release decision; see `family-base-ai.md`.
- `GEMINI_IMAGE_MODEL`: defaults to `gemini-nano-banana-2.1`; separate from the helper's text model.
- `AVATAR_AI_ENABLED=false`: disables new generations. The existing `FAMILY_AI_ENABLED=false` also disables them. Existing saved portraits and reset remain available.

The source uses the [documented Interactions image-editing API](https://aistudio.google.com/docs/image-generation). Live verification found that this model requires `response_format.mime_type=image/jpeg`; the API subsequently converts that image to WebP.

No hosted deployment or physical Android camera test was performed as part of this implementation.

## Verification

- API regression suite: `npm test --workspace @famsync/api`.
- Avatar provider, consent and local database lifecycle/access tests: `npm run test:avatars --workspace @famsync/api`. Integration fixtures use a local mock provider and are removed afterward; no real images or provider charges are involved.
- Mobile tests, including batching, viewer isolation and stale-response handling: `npm test --workspace @famsync/mobile`.
- Mobile type check and Android bundle: `npm run typecheck --workspace @famsync/mobile` and `npm run bundle:android --workspace @famsync/mobile`.
- Web static preview build: `npm run build:preview`.

Live verification used a fictional adult cropped from the project's previously generated family-planning image. It covered generation with the configured key, a complete browser upload → generation → preview → save → reset flow using real local Auth and Storage, saved portrait loading in the profile and account menu, persistence after reload, and a 390-pixel phone viewport with no page overflow. The disposable QA account and its private storage objects were removed afterward. Evidence is under `output/avatar-qa/` and `output/playwright/avatar-*.jpg`.

Results: 87 API unit/regression tests, 92 mobile tests and 10 avatar provider/controller/integration tests passed. Web static export, mobile TypeScript and Android bundle export passed.
